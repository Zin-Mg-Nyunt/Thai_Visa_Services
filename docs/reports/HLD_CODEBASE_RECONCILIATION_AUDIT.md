# HLD vs codebase reconciliation audit

**Scope.** Read-only audit of `Project Resource/Thai Visa Management Web App – High-Level Design (v0.9).md` (1,347 lines, every section) against the code at commit `7eef719` (branch `phase-4-step-5`, clean working tree). The supporting documents were checked where the HLD defers to them: `docs/JOB_SEARCH_BUSINESS_RULES.md`, `docs/JOB_SEARCH_TECHNICAL_DECISIONS.md`, `docs/CLAUDE_MD_PROPOSAL.md` and `docs/reports/*`. There is no root `CLAUDE.md`.

**Rule of this audit.** The current code is the source of truth. Where the HLD and the code disagree, the HLD is reported as outdated, unless the code looks internally inconsistent; those cases are in Section F. Nothing was changed: no code, no database, no HLD.

**Labels.**

| Label | Meaning                                   |
| ----- | ----------------------------------------- |
| A     | Matches the code                          |
| B     | Outdated HLD                              |
| C     | Duplicated or contradictory documentation |
| D     | Missing from the HLD                      |
| E     | Implementation unclear or not verified    |
| F     | Possible implementation defect            |

"L" numbers are line numbers in the HLD.

---

## A. Executive summary

**Overall accuracy.** The business rules of the HLD are largely accurate. Its **status and history text is badly out of date**: about a third of the discrepancies are status labels, "not built yet" lists, "pending" plans and "unverified" notes that the commits since 2026-11-17 have overtaken.

**Areas that match the code (verified):**

- **Job Search** (Section 4.7, as a whole):
    - the five statuses and the transition table (`WorkerCaseStatus::allowedNext`)
    - Add Worker and reassignment
    - Hired → Cancelled with its refusals
    - resolve-and-close, with the deleted-person auto-cancel
    - whole-service cancellation
    - live Job Order Money and Unassigned
    - the Complete-engagement locks
    - the four cards and the manpower warning
    - the engagement document matrix
- **The money formulas:**
    - received, remaining and kept
    - payment status
    - Outstanding, with deleted Persons excluded
- **Clients:**
    - phone (E.164, unique among active people)
    - JPG-only photo up to 2 MB
    - delete confirmed by typing the phone
    - soft delete
    - files removed after commit
- **Service catalogue:**
    - two levels, with the parent and child checked by the backend and the database
    - fee fallback
    - Job Search excluded from Add Service
    - soft delete
- **Documents:**
    - PDF up to 5 MB, JPG/PNG up to 2 MB, type read from the content
    - signed URLs of 2 minutes on Spaces
    - access log
    - Job Search documents never in the portal
- **Client portal:**
    - a 48-character token
    - the PIN is the last 4 phone digits
    - 5 wrong PINs lock the client for 15 minutes, counted per client
    - an admin can unlock
    - logout of one client at a time
- **Landing statistics (D1):** definitions and cache.
- **Website appearance (D2):** formats, content checks, keys, old files removed after commit, versioned image URLs, publishing refused without a logo and favicon.
- **Retry helper:** 3 attempts, 5-second timeout always restored. It is now proven on MySQL.

**Most important outdated or contradictory rules:**

1. **The Business Dashboard "shows the Unassigned figure".** This appears in the HLD (L24, L474, L1313) and in **both authoritative Job Search documents** (Business Rules L444; Technical Decisions L721 and L812). The code shows **no** Unassigned figure: commit `3fade79` folded it into Total Received, and a test checks that it is absent. Because the HLD says those documents win when they disagree with it, all three files must be corrected together (R02).
2. **Profit.** Section 1 (L47) says "profit reporting (profit = received money)", and Section 4.2 (L166) lists "profit" with "Job Search profit is included". The code and Section 13.1 (L1218) show Profit as **Coming soon**, with no figure (R04, R12).
3. **Status text.** The header (L3, L17, L22, L26, L38, L41), Section 5 (L802–L819), Section 9.1 (L941, L957–L971), Section 12 (L1058), Section 12.1–12.4 and Section 13.3 describe code that is now committed, built and tested on MySQL as "draft", "uncommitted", "not built" or "not verified" (R01, R03, R37, R47, R48, R53–R58).
4. **App-wide masking of query values in logs** is listed as "not approved" (§12.2, L1166). The code enables it on every database connection (`config/database.php`, commit `dd8c25e`) (R55).
5. **Settings.** Section 4.2 (L169) offers a "default currency" and a "document-lock default". The currency is a fixed, read-only THB, and the documents-locked default was not built (step 5b.2 was skipped by the user) (R14).
6. **Hero image without an upload.** Section 4.11 (L615, L627) says the hero area "stays blank". The code shows the built-in illustration with a "Sample photo" tag (R26).
7. **Client portal profile** (§4.1, L156) lists "remarks" and only "Deposit / Fully Paid". The portal never sends remarks, and also shows Unpaid (R09).

**Important missing documentation:**

- **Security controls:** headers, CSP in Report-Only mode, HSTS, trusted hosts that fail closed, query-value masking, and the rate limits.
- **Publishing:** what is shown before and after publishing.
- **Website content rules:** the fixed social platforms and the text limits.
- **Payments:** only Cash, and no edit or delete.
- **Service rules:** Job Search cannot be deleted; sub-services need no public description.
- **Client and portal details:** the `+66` phone default, the 24-hour PIN failure window, the locale cookie, the clients payment filter, and the `db:check-server` command.

**Possible implementation defects** (Section F, not fixed):

| #   | Finding                                                                                                                                         |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| F1  | The CI runs on pushes to `main`, but the repository's branch is `master`, so pushes never trigger CI.                                           |
| F2  | An unknown tracking token returns 404 while a valid one shows the PIN page, which conflicts with "do not reveal whether a token exists".        |
| F3  | Refused settings attempts return 403 but are not logged.                                                                                        |
| F4  | Failed file deletions after Person deletion are only written to the error log; there is no recovery list. The HLD itself marks this as pending. |
